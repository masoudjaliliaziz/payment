۱. هویت‌سنجی و مدیریت دسترسی (RBAC)

امنیت و احراز هویت

  • Windows Authentication: استفاده از پروتکل NTLM برای احراز هویت مستقیم با سرورهای SharePoint.
  • Effective Permissions API: استعلام لحظه‌ای مجوزهای کاربر از طریق effectivebasepermissions.
  • بررسی بیت‌های دسترسی:
    • High & 1: دسترسی مشاهده (Read)
    • High & 2: دسترسی ویرایش (Edit)
    • High & 4: دسترسی حذف (Delete)

سیستم عیب‌یابی مجوزها

  • PermissionDebugger: ابزاری داخلی برای مشاهده وضعیت ModerationStatus و UIVersion هر تراکنش.
  • Audit Trail: رهگیری ویرایشگر نهایی (EditorId) و تاریخ آخرین تغییرات برای شفافیت مالی.

۲. موتور تسویه هوشمند (FIFO Engine)

الف) الگوریتم توزیع مبالغ پرداختی

سیستم با استفاده از منطق First-In-First-Out، مبالغ واریزی را بر اساس اولویت تاریخ سررسید روی بدهی‌ها توزیع می‌کند:

// 1. مرتب‌سازی صعودی بر اساس روز سال const sortedDebts = [...debtList].sort((a, b) => Number(a.dayOfYear) - Number(b.dayOfYear)); // 2. کسر مبلغ پرداختی از قدیمی‌ترین بدهی for (const debt of sortedDebts) { const currentDebtAmount = Number(debt.debt || 0); if (totalPaid >= currentDebtAmount) { debt.remaining = 0; totalPaid -= currentDebtAmount; } else { debt.remaining = currentDebtAmount - totalPaid; totalPaid = 0; } }

ب) قانون طلایی ۶۰ روز (Special Rule)

برای انبار اصلی با Parent GUID خاص (7fc2d...)، سیستم به صورت خودکار یک فرجه ۶۰ روزه به تاریخ راس بدهی اضافه می‌کند تا انعطاف‌پذیری مالی بیشتری ایجاد شود.

۳. محاسبات مالی و راس‌گیری وزنی

فرمول راس‌گیری (Weighted Average)

محاسبه میانگین وزنی تاریخ‌ها برای تعیین نقطه تعادل زمانی پرداخت‌ها:

Σ (Pricei × DayOfYeari) / Σ Pricei
  • دقت محاسبات تا سطح روز (Floor/Round).
  • تبدیل خودکار خروجی به تاریخ شمسی با استفاده از Intl.DateTimeFormat.

تراز مالی زنده (Live Balance)

  • بستانکار: زمانی که مجموع پرداختی‌های تایید شده خزانه از کل بدهی‌ها بیشتر باشد.
  • بدهکار: نمایش مانده بدهی خالص پس از کسر تمامی واریزی‌های در جریان و نهایی.

۴. سیستم ثبت هوشمند و پردازش بارکد

پردازش QR صیادی

  • QR Parsing: تجزیه رشته متنی اسکن شده برای استخراج همزمان کد صیادی (۱۶ رقم آخر) و کد ملی صاحب چک.
  • Haghighi vs Hoghoghi: تشخیص خودکار نوع هویت بر اساس طول کد استخراج شده (۱۰ رقم برای حقیقی، ۱۱ رقم برای حقوقی).

کنترل‌های اعتبارسنجی

  • Duplicate Detection: بررسی لحظه‌ای در دیتابیس برای جلوگیری از ثبت کدهای صیادی تکراری (به جز موارد رد شده).
  • Draft System: ثبت اولیه در لیست Draft قبل از تایید نهایی برای جلوگیری از مفقود شدن داده‌ها در صورت قطع اینترنت.

۶. معماری و پشته تکنولوژی

Core Technologies
